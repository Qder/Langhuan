# 兼容性验收 · 项目预览的支持边界

这个示例故意做成「跑不完整」的项目，用来验收：**预览提前、具体地说清楚哪里不行**，而不是让样式或脚本静默失效。

## 怎么用

1. 在琅嬛里「导入项目」，选这个文件夹（`examples/兼容性验收`）。
2. 打开 `index.html`，切到预览。

## 应该看到什么

预览顶部一条 **「预览可能不完整 · 4 类 4 处」** 的横条（默认收起，点开分类清单）：

| 类型 | 位置 | 影响 |
| --- | --- | --- |
| ES 模块导入（相对路径） | `js/module-app.js:3` → `./greet.js` | 可能不运行 |
| 脚本的 defer / async | `index.html:10` → `js/app.js` | 执行时机可能改变 |
| 外站资源（需要联网） | `index.html:8` → `cdn.jsdelivr.net/…github-markdown.css` | 需要联网 |
| 找不到的本地文件 | `index.html:30` → `img/missing.png` | 预览会失真 |

页面上的可见证据：

- 第 1 段的黄框文字**没有变绿**：defer 脚本在 DOM 就绪前就跑了（内联时属性被去掉）。
- 第 2 段的黄框文字**没有变绿**：模块脚本整支没跑起来。
- 「缺了一张图」下面留一个破图位置；下面那张 logo 正常显示（已内联成 data URL）。
- `.from-import` 那段虚线框**能看到**（`@import` 已按被导入文件目录展平进预览）。

## 还应该能用（这是本期的重点）

- 点预览里任意元素 → 元素检视抽屉照常打开，HTML / 样式 / 行为三段都在。
- 右键「定位源码」照常跳到对应位置。
- 顶部横条在流内、把预览往下推，**不盖住**页面内容，也不影响抽屉开合。

## 反例（确认不会乱报）

`examples/资源内联验收` 是「能完整预览」的项目：打开它时顶部**不应该**出现任何提示条。
