# 行为定位：点元素 → 谁绑了事件 → 跳到第几行

本文写清「行为」段是怎么得出「`click → onSaveClick，app.js:12`」的，以及**哪些情况它一定找不到**——找不到时会明说，不会猜。

> 第二期之后，行为不是独立页签，而是「元素检视」抽屉里的第三段（HTML / 样式 / 行为一次全给）。
> 抽屉的触发方式、键盘、pin、跳转行为见 [docs/status/STATUS-element-inspector.md](status/STATUS-element-inspector.md)。

## 一句话

> 静态分析用户的 `.js` 文件与 HTML 内联 `<script>`，建一张「函数 / DOM 查询 / 事件绑定」符号表；
> 点预览元素时拿它的 `tag / id / class` 去反查，命中就给「事件名 + 函数名 + 文件:行」。

不做的事：运行时定位、插桩改写用户代码、sourcemap、行级变量追踪。

## 链路

```
导入项目 / 首次点击
  └─ acorn 解析 .js → content/.langhuan/index/js/<hash>.json（删掉能重建）
             │
点任意元素 ──┼─ bridge 回传 lh-element{ element, ancestors, range, text }（每次点击都发，按钮也算）
             │      element = 真正点到的那个元素（样式段会往上找祖先，行为不跟）
             │      ancestors = 最多 6 层祖先（html 不进链）
             │      range = 最近的 data-lh 标注区间（抽屉 HTML 段拿它给精确行号）
             ├─ 父窗口追问 lh-css-query → lh-css-hits{ hits, element, ancestors }
             └─ store.inspectElement
                    ├─ HTML 段：buildElementHtmlInfo(range / located / 文本)
                    ├─ 样式段：resolveCssHits(hits, cssIndexes)        ← 原有逻辑，未改
                    └─ 行为段：resolveBehaviorHits(target, jsIndexes)
```

`jsIndexes` 来自库快照（`/api/library`）；项目内 `.js` 缺索引时点一下会自动补建一次
（`buildLibraryJsIndex` → `PUT /api/library/file {jsIndex:true}`）。
HTML 的内联 `<script>` **不落索引文件**：每次点击用当前编辑内容现解析，行号偏移到宿主 HTML 的绝对行。

## 索引形状

`src/lib/locate/jsIndex.ts`：

| 符号 | 内容 |
|------|------|
| `functions` | 函数声明 / 表达式赋值 / 箭头 / 对象方法 / class 方法：名字 + 起止行 |
| `queries` | `querySelector` / `querySelectorAll` / `getElementById` / `getElementsByClassName`：归一后的选择器 + 行号 + 所在函数 |
| `bindings` | `X.addEventListener("event", handler)`：事件名 + 行号 + `X` 的静态选择器 + handler 名与起止行 + 所在函数 + 是否 document/window 级 |

「`X` 的静态选择器」只认这几种能静态确定的写法：

```js
document.getElementById("btn").addEventListener("click", onSave)   // #btn
const btn = document.getElementById("btn"); btn.addEventListener(...) // #btn（变量表）
document.querySelectorAll(".item")...                              // .item（查询侧）
document / window / document.body .addEventListener(...)           // delegated = true
```

`el`（函数参数）、`this.el`、`forEach(function (el) {...})` 里的 `el`：**归属不到**，只计入
`unresolved`，面板写「另有 N 处绑定无法静态归属」。

## 匹配算法与边界

1. 选择器按逗号切段（复用 `cssLocate.splitSelectorList`）。
2. 每段取**末尾复合选择器**，只认 `tag` / `#id` / `.class`：
   - 命中点击元素本身 → `match: "self"`（精确）
   - 只命中祖先链里某一层 → `match: "ancestor"`（父元素 / 可能是委托）
   - 都不中 → 不进结果
3. 依次剥掉尾部伪类/伪元素；带组合器（空格 / `>` / `+` / `~`）或伪类的判为**推断**（`precision: "fuzzy"`），
   因为只按末尾复合选择器判。
4. 出现属性选择器（`[data-x]`）等静态判不了的形状 → 标 `unsupported`，计入 `unresolved`。
5. 通配 `*` 不参与匹配（命中所有元素等于没信息）。

## 明确找不到的情况（面板会如实说）

| 情况 | 抽屉里的表现 |
|------|----------|
| 元素上没有任何绑定 | 行为段写「未在源码中找到直接绑定，可能通过事件委托注册」 |
| 有查询没绑定 | 上方空态 + 下方「相关查询（查了这个元素，但没绑事件）」 |
| document / window 上的监听 | 单独一栏「页面级监听（可能经由事件委托触发）」 |
| `el.addEventListener` 归属不明 | 「另有 N 处绑定无法静态归属（绑定对象是变量 / 参数 / this）」 |
| 属性选择器 | 同上计入无法判定 |
| `app.js` 语法错误（含 JSX/TS 写在 .js 里） | 索引不产出任何符号，面板显示「`app.js` 解析失败：…」，不给行号 |
| Vue / React 等框架渲染出的 DOM | 源码里没有对应的查询与绑定 → 未找到 |

## 索引过期怎么办

索引在**导入项目时**建立，点元素时缺了会补建。改了 `.js` 之后：

- 索引里有这条文件的旧版本 → 面板仍按旧行号跳（和 CSS 索引同一取舍）；
- 想让行号立刻正确：删掉 `content/.langhuan/index/js/` 后重新打开文档（会重建），或重新导入项目。

## 硬约束

- 用户源文件只读：所有索引都在 `content/.langhuan/index/js/`，删掉可重建。
- 预览 iframe 的 sandbox 仍是 `allow-scripts allow-popups allow-forms`，没有 `allow-same-origin`。
- 桥接脚本改的是 `bridge.client.js`，`bridge.generated.ts` 由 `npm run gen:bridge` 生成。
